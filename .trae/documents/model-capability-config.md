# 模型分类与输入模态配置改造

## Context

不同模型可接受的输入不同，应用无法可靠自动探测，需要由用户在模型配置中显式声明。本次先建立准确、可持久化的输入能力配置，供后续图片、音视频及输入策略使用；不实现运行时多模态处理，也不加入工具调用或图片传入位置配置。

采用“模型类别 + 输入模态”。输出模态当前没有消费方，且与模型类别部分重复，本次不保存；待实现生成响应渲染时再依据真实契约设计。不保存 `supportsMultimodal`：`多模态输入`由 `inputModalities.length > 1` 派生，避免重复事实源和含义不清的开关。开发阶段不做旧配置字段兼容或静默修补。

## 1. 扩展共享模型配置契约

修改 `packages/llm/types.ts`：

- 新增 `ModelCategory = 'language' | 'image' | 'audio' | 'video'`。
- 新增 `Modality = 'text' | 'image' | 'audio' | 'video'`。
- `ModelDef` 新增必填字段：`category`、`inputModalities`。
- 导出类别、模态常量及类型守卫，供服务端校验和 UI 控件共用，避免各自维护字符串清单。

类别表示主要任务类别，输入模态表示模型能接受的参数，两者独立描述，不增加“类别同名模态必须出现在输入中”之类的约束。例如图片生成模型可以只接受文本，语音识别模型可以只接受音频。

## 2. 默认配置与服务端严格校验

修改 `service/storage/models.ts`：

- 为两个 DeepSeek 默认模型显式补齐 `category: 'language'` 与 `inputModalities: ['text']`。
- 在现有 `parseModel` 中解析并返回新增字段，继续由 `parseVendors` 作为 models.json 读取和 PUT 请求的统一边界。
- 校验类别合法、输入模态为非空数组、每项属于已知模态且数组内无重复项。
- 缺字段、未知值或空数组直接报错，不提供旧数据回退，也不自动猜测能力。
- 保留现有必填字符串、path 和唯一性规则。

`shared/dto.ts`、`service/routes/models.ts` 已分别复用 `Vendor` 和 `parseVendors`，无需新增平行 DTO 或重复校验。

## 3. 重构模型编辑项并接入能力配置

修改 `ui/views/ModelModal.vue`：

- 从共享契约导入类别、模态常量与类型；中文标签使用本地类型完整映射。
- 新增模型时默认 `language` + `['text']`，每个模型创建独立数组；切换类别时保留用户已选输入模态，不隐式重置。
- 将现有单行表格模型项改为结构化卡片：第一行编辑 Model ID、Path、类别和删除操作；第二行放置“输入模态”复选框组，避免在原表格中挤入复杂控件。
- 输入模态超过一项时显示“多模态输入”派生标识；不增加可手工切换的多模态开关。
- 扩展现有 `validate()`，用中文提示未选择输入模态；保存仍复用 `setVendors` 和 `models.load()`，不改变接口流程。
- 样式按模型卡片、基本信息行、模态配置组嵌套组织，保持现有滚动边界和主题 token。

## 明确不改

- 不增加输出模态字段。
- 不修改 `ui/stores/models.ts`、HTTP 接口结构或 provider 调用。
- 不实现图片/音视频消息、工具调用能力或 `user/tool_result` 图片位置。
- 不新增旧 models.json 的缺字段推导逻辑。

## 验证

1. 运行 `npm run typecheck`，确认共享类型、服务端和 Vue 模板均通过。
2. 启动 Electron 开发环境，分别新增语言、图片、语音、视频模型，调整输入模态，检查切换类别不重置选择、多模态输入派生标识和删除操作。
3. 保存并刷新应用，确认 models.json 与 UI 完整往返，类别和输入模态不丢失，不同模型的草稿数组互不影响。
4. 验证前端会阻止空输入模态；通过 PUT 冒烟确认非法类别、未知模态、空数组、重复模态和缺字段均被服务端拒绝。
